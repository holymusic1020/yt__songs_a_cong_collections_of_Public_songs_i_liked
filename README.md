# 🌙 yt-auto — Nix Speech

> **🚀 IMPATIENT? Start here → [`docs/LAUNCH.md`](docs/LAUNCH.md) — one sitting, running in ~45 min.**

A fully automated YouTube music channel in a box. Every ~3 days, a GitHub
Actions cron job wakes up, **composes an original track from scratch**
(drift phonk / deep dark-pop / dark ambient), paints cover art, writes the
title + description, renders the video, and publishes it through the
**official YouTube Data API** — then goes back to sleep. No server, no
keep-alive hacks, $0.

```
cron (every ~3 days) — ONE RUN = ONE FULL RELEASE
   └─ src/main.py
        ├─ composer.py     numpy synthesizer → song.wav     (6 engines: phonk/dark-pop/ambient/lo-fi/waltz/house)
        ├─ copy_ai.py      Gemini TEXT → fresh hooks/lines  [fallback: static banks]
        ├─ art_gemini.py   Gemini IMAGES → cover + 4 scenes [fallback: art.py procedural]
        ├─ video_gemini.py Veo cinematic clip               [fallback: Ken Burns slideshow]
        ├─ video_render.py clip-loop / xfade slideshow + OFFICIAL chip
        ├─ metadata.py     official label copy + shorts packaging
        ├─ shorts.py       hook-window detector → lyric cards → 1080×1920 short
        ├─ uploader.py     YouTube API v3, native SCHEDULED publishing:
        │                  video now+0–5h (random, sec) · short now+1–3h
        └─ state.py        release memory, committed back to repo
```

## 💰 GitHub limits — you're safe (public repo)
- **Public repo = unlimited Actions minutes.** $0 forever. (Private = 2,000 min/mo.)
- **The random delay costs ZERO minutes.** The run uploads with YouTube's
  `publishAt` and exits in ~3–8 min; **YouTube's** servers publish 1–5h later.
- 2 uploads/run = 3,200 of 10,000 daily API units. Comfy.
- Verdict on alternates: no HF Space, no n8n — a cron action is strictly
  better for this workload (nothing to keep awake, nothing to babysit).

## 🎬 Visual chain (auto, with fallbacks at every step)
1. **Veo clip** (`video_gemini.py`) — environments-only prompts (no people →
   no plastic hands/faces), 35mm/grain language, negative prompts. Looped to
   song length. ⚠️ Veo needs a Gemini key whose tier includes video gen
   (billing enabled in AI Studio). No access? It auto-falls to…
2. **4-scene Ken Burns slideshow** — Gemini paints 4 matching shots of the
   same song-world, ffmpeg zoompans + crossfades them to the music.
3. **Static branded cover** — always works, zero deps.
Anything failing downgrades with a log line, never kills the run.

## Why it's built this way (the clever part)

- **GitHub Actions cron > 24/7 server.** The machine only exists for the
  ~5 minutes it takes to make a song. Nothing to keep awake, nothing to break.
- **Official API, not browser bots.** Auto-uploading on a schedule is a
  legitimate, supported YouTube feature — there is nothing to dodge, so the
  channel isn't one policy sweep away from death.
- **AI disclosure is automatic** (`containsSyntheticMedia: true`). YouTube
  *requires* declared synthetic media; declaring it keeps you bulletproof.
- **Music is synthesized, not sampled.** Every note is generated by our own
  code → zero copyright claims, zero license problems, and it's
  **monetization-safe** from day one.
- **Everything is a module.** Want a fancier AI music model, better art, or
  a second channel? Swap one file, keep the pipeline.

## Setup (one time, ~30 min)

1. **Repo**: push this folder to a GitHub repo (public = free unlimited
   Actions minutes).
2. **Google Cloud** (console.cloud.google.com): create a project → enable
   **YouTube Data API v3**.
3. **OAuth consent screen**: External → fill the basics → **PUBLISH the app**
   (status "In production"). ⚠️ If you leave it in "Testing", refresh tokens
   **expire every 7 days** and the pipeline breaks weekly. In production you
   may see an "unverified app" warning — for your own account you just click
   through it, and the token lives indefinitely.
4. **Credentials**: create OAuth client → type **Desktop app** → download
   the JSON.
5. **Mint the token** (on your machine):
   ```bash
   pip install google-auth-oauthlib
   python tools/get_refresh_token.py    # browser opens, log in
   ```
6. **GitHub secrets**: Settings → Secrets and variables → Actions → add
   `YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN`.
   Optional but recommended: `GEMINI_API_KEY` — powers **three brains at once**:
   fresh hooks/lyrics text, cover images + slideshow scenes, and Veo clips
   (if your key's tier has video access; otherwise it falls back automatically).
   Pin models with `GEMINI_IMAGE_MODEL` / `VEO_MODEL` if you like.
7. Done. Hit **Actions → publish episode → Run workflow** for EP.001, or
   wait for the cron.

### About OAuth Playground ("isn't it permanent?")

Playground hands you the *same kind* of refresh token, just held by a janky
tool (and often Google's **shared** playground client — bad for quota and
security). The 7-day Testing-mode expiry kills it there too. Our own client
+ Production status = token that only dies if you revoke it, change your
password, or don't use it for 6 months (we use it every 3 days).

## Tuning knobs

| Want | Where |
|---|---|
| Different post frequency | `cron:` in `.github/workflows/publish.yml` |
| Longer/shorter songs | default `--length` range in `main.py` |
| New genre | add a builder in `composer.py` + banks in `metadata.py` |
| Channel name / vibe | `CHANNEL` + banks in `metadata.py`, cover prompts (`MOODS`) in `art_gemini.py` |
| Force cover style | `--art-mode gemini` / `--art-mode procedural` |
| Scheduled future publish | pass `publish_at` to `uploader.upload()` |

## 🛡 Pre-solved future problems (the month-3 audit)

| Problem | Built-in cure |
|---|---|
| Double-clicking "Run workflow" | `concurrency` lock — runs queue, never duplicate EP numbers |
| Repeating song titles over months | used-name recall in state → auto "II"/"III" suffixes |
| Channel drifting off-taste | adaptive weights: analytics reads views, gently favors winning genres (15% floor = exploration never dies) |
| Shorts funneling nowhere | auto-comment bridge under every short (pin it on your weekly ritual — API can't pin) |
| pip update breaks a dep | bounded version pins in requirements.txt |
| State push fails mid-run | `git pull --rebase` self-heal before push |
| GitHub **60-day rule**: scheduled workflows auto-disable in idle repos | our state commits = activity, repo never idles. If you EVER get the "workflow disabled" email → Actions tab → one click re-enable. Done. |
| Something breaks silently | GitHub emails YOU on any failed run + every log opens with the 🩺 doctor report + release summary posted to the run page |
| Lost refresh token (`invalid_grant`) | re-run Phase 4 (5 min), update the secret. Tokens die only from: password change, revoke, 6-month no-use (we use it every 3 days), or app back to Testing |
| **Uploads locked Private** (new API project rule) | free YouTube API compliance audit — see `docs/LAUNCH.md` top. Timeouts mid-upload auto-retry; quota exhaustion stops cleanly (no loop-burn) |
| Loudness penalty / quiet audio | every render mastered to **-14 LUFS / -1 dBTP, AAC 320k** (YouTube's own normalization target) |
| Identical tag blocks flagged as spam | rotating tag sets + unique track-name tag per EP |
| Silent failures | optional `NOTIFY_WEBHOOK` Discord alert on any failed run |
| quota exhausted | quotaError → just wait; resets midnight Pacific. ~3,200/10,000 units per release |
| Synthetic-media crackdowns | flag stays ON + quiet production line = you survive purges that kill the sneaky channels |

## House rules (kept honest on purpose)

No view-botting, no click-farms, and the random publish windows are NOT a
disguise — uploads go through the official API under your project, so
YouTube always knows. Their real purpose is **peak-hour discovery**: read
`docs/PLAYBOOK.md` rule 9. The synthetic-media flag stays ON; viewers get
the official-label look while the platform stays fully informed. Growth
comes from consistency, loops, and watch time — the stuff that survives
algorithm changes. That's the actual lifetime-chill strategy. 🥷🌙
